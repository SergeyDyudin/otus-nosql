# Отчет

### Примеры применения графовых баз данных

1. Социальные сети

В социальных сетях основными сущностями являются пользователи, а также связи между ними: дружба, подписки, лайки и комментарии. Часто требуется выполнять запросы вида:
- найти друзей друзей
- определить общих друзей
- предложить рекомендации по знакомству

Такие задачи требуют эффективного обхода связей между сущностями на несколько уровней. Графовая база данных позволяет указывать пользователей как узлы, а их связи как рёбра, что делает выполнение подобных запросов быстрым и удобным.


2. Рекомендательные системы

В системах рекомендаций (например, фильмы или товары) используются следующие сущности:
- пользователи
- фильмы или товары
- жанры
- оценки

Типичные запросы:
- найти похожие фильмы
- предложить пользователю контент на основе его интересов
- определить, что смотрели другие пользователи с похожими предпочтениями

Графовая модель позволяет эффективно анализировать взаимосвязи между пользователями и объектами, что делает её особенно подходящей для рекомендаций.


### Реализация аналогичных neo4j команд в реляционной базе данных (PostgreSQL)

Для сравнения рассмотрим модель фильмов, режиссёров и актёров.

```sql
CREATE TABLE directors (
    id SERIAL PRIMARY KEY, 
    name TEXT 
); 
CREATE TABLE movies ( 
    id SERIAL PRIMARY KEY, 
    title TEXT, 
    year INT 
); 
CREATE TABLE directed ( 
    director_id INT, 
    movie_id INT 
);
```

Создание данных

```cypher
create (:Director {name:'Joel Coen'}) -[:CREATED]-> (:Movie {title:'Blood Simple', year:1983})
```

```sql
INSERT INTO directors (name) VALUES ('Joel Coen'); 
INSERT INTO movies (title, year) VALUES ('Blood Simple', 1983); 
INSERT INTO directed (director_id, movie_id) VALUES (1, 1);
```

Получение связанных данных

```cypher
match (d:Director) -[r]- (m:Movie) return d, r, m
```

```sql
SELECT d.name, m.title 
FROM directors d 
JOIN directed dr ON d.id = dr.director_id 
JOIN movies m ON m.id = dr.movie_id;
```

Удалить связи ноды

```cypher
match (n:Director {name:'Ethan Coen'}) -[r]- () 
delete r
```

```sql
DELETE FROM directed
WHERE director_id = (
    SELECT id FROM directors WHERE name = 'Ethan Coen'
);
```

### Сравнение Neo4j и реляционной базы данных (PostgreSQL)

В Neo4j удобнее работать со связанными сущностями. Графовая модель позволяет создавать сразу несколько узлов и связей между ними в рамках одного запроса в отличии от postgreqsl, где каждую сущность необходимо создавать отдельным запросом.

Также Neo4j предоставляет удобный механизм работы со связями как с полноценными объектами. Например, удаление всех связей у узла выполняется одной простой командой.

```cypher
match (n:Director {name:'Ethan Coen'}) -[r]- () 
delete r
```
Данный запрос не зависит от количества и типов связей — база данных сама находит и удаляет все рёбра.

Кроме того, запросы в Neo4j описывают путь между сущностями, что упрощает чтение и понимание 
логики работы с данными.

В Postgresql выборка связанных данных менее наглядна, так как требует использования нескольких JOIN.
