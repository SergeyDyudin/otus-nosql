# Отчет

В состав кластера входит
- три шарды mongo-shard-{1,2,3}-rs-{1,2,3}
- каждой шарде replica-set по три реплики
- config-сервер в виде replica-set из трех реплик mongo-config-srv-{1,2,3}
- роутер mongos mongo-router-1

Запуск контейнеров производится через docker-compose [файл](../mongodb/docker-compose.sh-rs.yaml).

Настройка реплик и шардирования производится через запуск скрипта [init_cluster](../mongodb/init_cluster.sh).

### Шардирование данных

Возьмем коллекцию comments и будем её шардировать.
Ключем шардирования попробуем взять movie_id:
- высокая кардинальность
- часто используется в запросах

Подключимся к контейнеру
```sh
docker exec -it mongo-router-1 mongosh
```

Включим шардирование в бд
```sh
use meflix
```

```sh
sh.enableSharding("meflix")

```

Далее начинаем отключать контейнеры, входящие в replica-set shard-replica-set-1.
Отключаем PRIMARY - запрос продолжает возвращать ответ, так как replica-set выбрала нового PRIMARY.
Отключаем нового PRIMARY - голосование большинством за нового PRIMARY не работает и запрос через таймаут возвращает ошибку:
```sh
MongoServerError[FailedToSatisfyReadPreference]: failed on: shard-replica-set-1 :: caused by :: Could not find host matching read preference { mode: "primary" } for set shard-replica-set-1
```

Запускаем контейнеры в обратном порядке. Голосование проходит уже при наличии двух контейнеров и запрос начинает выполняться.


### Подключаем авторизацию

Для подлючения авторизации для реплик в шардах был добавлен проброс файла [mongo-keyfile](../mongodb/mongo-keyfile) в docker-compose в каждый контейнер и добавлен флаг --auth

Для создания этого файла необходимо выполнить:
```sh
openssl rand -base64 756 > mongo-keyfile
chmod 400 mongo-keyfile
```
