## Масштабирование и отказоустойчивость Cassandra

### Цель:
В результате выполнения ДЗ вы подготовите среду и развернете Cassandra кластер для дальнейшего изучения возможностей маштабирования и восстанавления Cassandra кластеров.


### Описание/Пошаговая инструкция выполнения домашнего задания:
Необходимо:
- Развернуть docker локально или в облаке
- Поднять 3 узловый Cassandra кластер.
- Создать keyspase с 2-мя таблицами. Одна из таблиц должна иметь составной Partition key, как минимум одно поле - clustering key, как минимум одно поле не входящее в primiry key.
- Заполнить данными обе таблицы.
- Выполнить 2-3 варианта запроса использую WHERE
- Создать вторичный индекс на поле, не входящее в primiry key.
- (*) Нагрузить кластер при помощи Cassandra Stress Tool (используя "How to use Apache Cassandra Stress Tool.pdf" из материалов).


### Критерии оценки:

- Задание выполнено - 10 баллов
- +5 баллов за задание со *
- Предложено красивое решение - плюс 2 балла


# Отчет

Запуск контейнеров с кластером cassandra производится через docker-compose [файл](../cassandra/docker-compose.yaml).

Для создания структуры KEYSPACE и загрузки тестовых данных используется [скрипт](../cassandra/init_cluster.sh).

После его выполнения получаем тестовую среду для хранения логов сервисов включающую в себя:
- keyspace logs
- таблица services
- таблица events (составной partition_key(service, log_date) и clustering_key(event_time)). Таким образом на одной ноде будут храниться логи сервиса за день. И они будут отсортированы по времени.
- Создан вторичный индекс для таблицы events по полю level фильтрации


```sh
cqlsh:logs> SELECT * FROM services;

 service              | description            | owner
----------------------+------------------------+---------------
payment-service       | Payment processing     | Payments Team
notification-service  | Notifications          | Notify Team
auth-service          | Authentication service | Auth Team

(3 rows)
```


```sh
cqlsh:logs> SELECT * FROM logs.events;

 service         | log_date   | event_time                      | level | message
-----------------+------------+---------------------------------+-------+------------------
 payment-service | 2024-02-27 | 2024-02-27 09:45:20.000000+0000 | ERROR |   Payment failed
 payment-service | 2024-02-27 | 2024-02-27 08:20:10.000000+0000 |  INFO |       Payment OK
    auth-service | 2024-02-26 | 2024-02-26 22:15:30.000000+0000 |  INFO | Password changed
    auth-service | 2024-02-27 | 2024-02-27 10:05:15.000000+0000 | ERROR |       DB timeout
    auth-service | 2024-02-27 | 2024-02-27 08:15:30.000000+0000 |  INFO |       User login

(5 rows)
```

### Запросы

1. Все логи конкретного сервиса за конкретный день

```sh
cqlsh:logs> SELECT * FROM events
        ... WHERE service = 'auth-service'
        ... AND log_date = '2024-02-27';

 service      | log_date   | event_time                      | level | message
--------------+------------+---------------------------------+-------+------------
 auth-service | 2024-02-27 | 2024-02-27 10:05:15.000000+0000 | ERROR | DB timeout
 auth-service | 2024-02-27 | 2024-02-27 08:15:30.000000+0000 |  INFO | User login

(2 rows)
```

2. Логи сервиса за день с фильтром по времени

```sh
cqlsh:logs> SELECT service, event_time, level, message
        ... FROM events
        ... WHERE service = 'payment-service'
        ... AND log_date = '2024-02-27'
        ... AND event_time >= '2024-02-27 09:00:00'
        ... AND event_time < '2024-02-27 12:00:00';

 service         | event_time                      | level | message
-----------------+---------------------------------+-------+----------------
 payment-service | 2024-02-27 09:45:20.000000+0000 | ERROR | Payment failed

(1 rows)
```

3. Найти все ERROR логи по всем сервисам (используем вторичный индекс)

```sh
cqlsh:logs> SELECT * FROM events WHERE level = 'ERROR';
```
